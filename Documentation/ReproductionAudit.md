# 再現率の厳密な集計と全入力評価の限界

集計日: 2026-10-15。対象は NOVA 3.6.0
(`1c6b88729f91c852c164ef71a32cc2bce83a1892`) と Built-in 0.1.7の描画互換修正
(`b001fcdc67389cabcb24f3d494ac0d6ed1f55401`)。
数値の原本は [再計算結果 JSON](Verification/ReproductionAudit20261015.json)。
この集計は記録の監査であり、下記画像群を新たに撮り直したものではない。
同日の[API互換修正](RuntimeAPICompatibility.md)に伴い、宣言分類と対象ソースを更新した。さらに[Exact分類の再評価](ExactParityProgress.md)で6項目を更新した。

## 結論

**全機能・全入力をまとめた単一の再現率は、現時点では算定不能（未定義）。**
これは 0% という意味ではない。以前の「98.8〜100%」は選択した画像テストの
許容誤差内合格率であり、全入力への再現率として使うことはできない。
既知の描画差とソース互換性の欠如があるため、完全互換100%とも判定できない。

再現率を `一致する入力の重みの合計 / 全入力の重みの合計` と定義するには、
対象機能、入力集合、各入力の重み、一致の意味が必要になる。
現在は任意の素材、数値、シーン、呼び出し順、ワールド、GPUなどを含む閉じた入力集合と
重みが定義されておらず、その全集合に対する証明もない。
浮動小数点が有限精度であっても、全機能の組み合わせやリソース・実行履歴まで
網羅したことにはならない。テスト件数を増やすだけではこの問題は解消しない。

以下では分母が定義できる数値を別々に示す。異なる単位の数値を平均した「総合点」、
近似機能への任意の部分点、無作為な利用分布を仮定した信頼区間は作らない。

## 全機能一覧の分類

[互換表](BuiltInCompatibilityMatrix.md)の66行すべてを、API・機能台帳と照合した。
分類、理由、代替策はJSONにも全行収録している。この66行は現在の機能分解であり、
全入力の独立した66回の試行や、形式的に証明された仕様の全集合ではない。

| 分類 | 項目数 | 判定の意味 |
| --- | ---: | --- |
| Exact | 34 | 検証したWindows経路の契約・計算が一致。全入力の同値証明ではない |
| Approximate | 29 | 代替実装と制約がある。再現度を一律の部分点には換算できない |
| Unsupported | 0 | 表の機能単位で代替なしと分類された行はない |
| Not Applicable | 3 | Lightmaps and vertex lighting、RenderGraph、URP compatibility mode |

対象外を除く**Exact分類比率は34/63 = 53.97%**。
対象外も含めた全行に対する比率は34/66 = 51.52%。どちらも**見た目の再現率でも、
全入力の一致率の下限でもない**。機能行を細分化するだけでも比率は変わる。
Unsupportedが0でも、URP専用API・APVデータ読み取りなどが使えるという意味にはならない。
それらの欠落はApproximateの制約欄やランタイムAPIの非互換分類に含まれる。

## API・素材宣言

| 対象 | 分母と結果 | 証拠の範囲 |
| --- | --- | --- |
| ShaderLabプロパティ宣言 | 889/889保持、100% | 今回ソースを再照合。属性・表示名・型・範囲・初期値・順序を含む |
| 公開／protected Editor宣言 | 台帳525/525収録、保持の既存検証525/525 | 今回は凍結台帳との照合。実行時リフレクションは0.1.6の既存Unity検証 |
| 元ランタイム宣言 | 21件中Exact 2、Approximate 6、ソース非互換13 | 元のコンストラクター・Setup・Resetの5宣言を復元。URP継承まで同じとは扱わない |
| APIの選択入力に対する観測 | 各Editorで188/188一致 | 10個のキーワード変換関数、128個の参照整理ケース、8個の頂点ストリームケース |

889はシェーダー別宣言数の合計で、共通名の重複を含む。525と21もメソッドだけではなく、
型・フィールド・定数・列挙値などを含む宣言数である。
ランタイムのExact 2件はDeprecationMessageの型と定数フィールドであり、
「ランタイムの描画機能が2/21再現できた」と解釈してはいけない。
Approximate 6件はScreenSpaceDistortion.Create()と復元した5宣言。
非互換13件はURPの継承・型・ライフサイクルなど。

188観測は[元の記録](Verification/Randomized20261013/summary.json)の両実装のSHA-256と照合した。
保存時の整形差は元のJsonUtility形式に復元して確認し、内容変更はエラーにする。
キーワード変換は列挙された値と`-1`・`int.MaxValue`を試しており、任意の整数すべてを
実行したわけではない。宣言保持と、関数の全入力・全呼び出し順の互換性は別である。

## 画像の合格率と完全一致率

保存済みの**各フレームの誤差値**から再集計し、記録済みの合否・件数とも照合した。
以下の3群を選択した明示的なマニフェストを使う。全検証の総和ではない。

| 検証群 | 許容誤差内 | 記録RGBの画素完全一致 | 版・時点 |
| --- | ---: | ---: | --- |
| 実素材コーパス | 1,994/2,018 = **98.81%** | 1,972/2,018 = **97.72%** | 0.1.2の既存記録 |
| ランダム素材・機能 | 3,328/3,328 = **100%** | 2,874/3,328 = **86.36%** | 2026-10-13、元ソースハッシュ保存済み |
| 環境光・補間 | 1,008/1,008 = **100%** | 974/1,008 = **96.63%** | 0.1.6の記録 |

合格基準は既存のまま、平均RGB誤差≤0.01、最大チャンネル誤差≤0.08、
平均RGB誤差>0.02の画素割合≤1%。画素完全一致は保存RGBの各誤差が0であること。
HDR内部値、アルファ、未撮影時刻や視点まで一致したという意味ではない。
また86.36%は「見た目が86.36%似ている」ではなく、完全一致した**画像件数の割合**である。

実素材の不合格24件はheal02の透明オブジェクトの描画順による差。
Unity 6で元実装とポートの両方がネイティブクラッシュするpfb_eff_fireは同Editorの
画像分母には入っていない。この除外を成功として数えない。
元レポート: [実素材](AssetCorpusVerification.md)、[ランダム](RandomizedParityVerification.md)、
[環境光](AmbientLightingParity.md)。

異なる版・条件の群を合算した単一の「最新再現率」は出さない。
古い実素材・ランダム全件を今回0.1.6で再撮影したわけではない。
red記録、修正前の環境光失敗、重複するretained-original22を加算しない。
SDK/AAOの比較は主にポート同士の比較であり、本家との再現率の分母には入れない。

## 全入力を判定するために残る範囲

| 入力群 | 現在の台帳・観測 | 全入力について不足するもの |
| --- | --- | --- |
| 数値・モード | Float 573、Range 144、Vector 27、Color 30宣言 | 全ビット値、範囲外・特殊値の契約、全組み合わせ、境界と分岐の同値証明 |
| 画像リソース | 2D 51、2DArray 32、3D 32宣言 | 任意の画素・解像度・ミップ・圧縮・import設定・サンプラーの全集合 |
| シェーダー経路 | キーワード、パス、頂点・Custom Dataの個別テスト | 有効なキーワード全組み合わせ、全頂点入力、深度・ステンシル・ブレンドとの直積 |
| シーンと時間 | 既存のライト・曲面・スケール・鏡・Canvas等のケース | 任意の形状、重なり、灯数、プローブ、カメラ、時間変化、オブジェクト生成破棄 |
| C# APIとEditor | 宣言台帳、選択した引数・Undo・GUI・寿命テスト | 全引数、オブジェクト状態、呼び出し順、失敗経路、GUI操作の同値性 |
| 実行環境 | 記録ごとのWindows D3D、Unity 2022/6、SDK/AAO条件 | 任意GPU・ドライバ・ワールド、最新版VRChat実機／HMD、AAOの全設定 |

既知の反例・制約には、透明ソートの同順位、局所SHとシーン環境プローブが異なる場合の
反射代替、重なる歪みと8x/9xフィルタ、URP専用型のソース非互換がある。
Forward+はBuilt-in追加パス、APVはLPPVによる代替で、元の基盤・データ互換を実装したものではない。

```sh
python3 Tests/Parity/analyze_reproduction.py --output Documentation/Verification/ReproductionAudit20261015.json

python3 -m unittest discover -s Tests/Docs -p 'test_*.py'
```

集計器は空の分母を100%にせず、欠落・重複フレーム、非有限誤差、不正な合否、
分類の不一致、API内容の改変を検出する。41個の参照ファイルのSHA-256を保存している。
新規10件を含むParity **18/18**、既存Docs **4/4**合格。実装前の失敗も確認した。
集計器はシェーダー・実行時処理・ゴールデン画像・判定しきい値を変更しない。
実行時APIの修正と再コンパイル・描画検証の結果はRuntimeAPICompatibility.mdに分けて記録する。
