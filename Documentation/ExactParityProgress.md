# Exact分類へ向けた修正と再評価（2026-10-15）

対象はNOVA 3.6.0とBuilt-inの`3b764095b35121828b1d295ac106b2796455f7fe`。
機能表の66行、対象外3行、Exactの定義、Windows D3D11/12という範囲は変更していない。
**Exactは28/63から34/63（53.97%）へ進んだ。100%は未達で、29項目はApproximateを維持する。**
これは機能分類の比率であり、全入力の同値証明や見た目の再現率ではない。

## 実際に直した差

### 距離フェード

本家の`Particles.hlsl:DepthFade`は投影した深度を`LinearEyeDepth`で線形化する。
以前の移植版は実際の視点距離へ置き換えていたため、正投影・斜交投影で異なっていた。
また幅を最低1e-4に制限しており、負の幅と小さな正の幅も本家と違っていた。

ラスタライズ済みの深度を利用して本家の式へ戻した。追加のvarying・テクスチャ参照・
パス・画面コピーはない。幅ゼロなど本家の特異点はGPUの演算に従う。
過去の最適化シェーダーから呼ばれるベクトル引数のヘルパーは、旧来の動作で保持した。
既存生成物を壊さず、新しい投影動作を反映したい生成物は再生成できる。
シェーダー名、プロパティ、初期値、Editor APIは変更していない。

独立した本家式のGPUオラクルと実際の描画を比較した。4種のUberとDistortionについて、
透視・正投影・斜交投影・鏡・負スケール・負の幅・微小幅の35ケースを用意した。
既存の視点距離に対するテストは、同じ画角の透視カメラで実距離の意味を維持するよう修正した。
数値の判定幅や画像基準は緩めていない。正投影そのものは新しい本家式比較で検証する。

### 入れ子のカメラ

親カメラで合成処理を使うと、NOVAコンポーネントのない子カメラへ「シェーダー側の
歪みを止める」状態が漏れ、鏡などで歪みが消えていた。全カメラの開始・終了を、
合成用コンポーネントが有効な間だけ監視し、カメラごとの状態を保存・復元する。
子の描画中に最後のコンポーネントが無効になった場合も、外部状態まで復元する。
VRChatアバターへ新しいC#コンポーネントを追加するものではない。

通常・反射・プレビューの3カメラ種と合成処理の有無を組み合わせた6画像比較に、
描画中の無効化と登録解除を加えた7ケースが通った。通常のカメラ破棄後に登録解除されることも追加で検証した。
初期テストにはUnityが許可しない描画コールバック内のDestroyImmediateが含まれていたため、
それは製品の不具合数に含めず、正当な無効化と通常の破棄で検証した。
Unityの[描画開始通知](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Camera-onPreCull.html)と
[描画終了通知](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Camera-onPostRender.html)を利用する。

距離フェード以外の5項目は、過去に直していた計算と検証を機能表へ反映した再評価であり、
今回5種類の新しい描画実装を追加したという意味ではない。
既存画像は再生成・置換していない。対象を絞った既存画像件数は互いに重複するテスト群と
合算して「全機能の成功率」にしていない。対象外のGPU、退化した法線、他の行で扱う
ライト選択・影・描画順まで同じとは判定しない。

## 負荷の実測

RTX 5070 Ti / Windows D3D11 / Unity 2022.3.22f1、1920×1080の非表示Playerで、
修正前`d9636c0`と修正後の独立したシェーダーを比較した。4種類のUberを対象に、
フェード無効の通常設定、有効の複合設定、8枚の重なり、反射したカメラ、クリップ付き
UI Lit＋8ライトの18条件。各条件3回のABBA、各ブロック64フレームの準備と128計測、計216ブロック。
GPUはタイムスタンプ、CPUは描画コマンド送信区間、メモリは使用中のネイティブリソースを記録した。
計測中は他の検証Editorを起動せず、ユーザーのアプリは変更していない。

**18/18条件で、増加がmax(5%, 0.02ms)以内、描画回数の増加なし。**
最も大きい増加はクリップ付きUI Lit＋8ライト＋8枚重ね＋鏡で、GPU中央値が
4.076992→4.111024ms、ABBA組の差の中央値が+0.034560ms（許容0.203850ms）。
この条件の描画回数は128→128。CPU中央値の差は全条件で最大+0.024250ms。
材料とRenderTextureの測定メモリ差はいずれも0バイトだった。

生データ・集計・ソースハッシュは`Documentation/Verification/ExactParity20261015/gpu-*`に保存した。
これはカメラの限られた描画区間の測定で、VRChat全体のフレーム時間ではない。
DistortionのGrabPassとカメラコールバックのCPU費用はこの測定に含めていない。
測定ウィンドウは表示していない。
